# 第九章参考实现验证

本次验证使用单核 QEMU 8.2.2、128 MiB 内存、GNU RISC-V GCC 13.2.0 与 GDB 15.1。设备采用 VirtIO MMIO modern 模式，显示尺寸为 1280×800。验证限定为本章教学环境，不代表多核或任意硬件平台验证。

## 功能验收

执行 `make build`、`make test-ch9`，全部通过。

| 检查 | 实际结果 |
| --- | --- |
| 内核及配套用户程序交叉编译 | `-Wall -Werror` 通过 |
| UART shell | 可输入完整命令并回显；无输入时线程阻塞 |
| `filetest_simple` | 输出 `file_test passed!`；独立读盘核对 `filea` 为 `Hello, world!` |
| `huge_write` | 完成 1 MiB 写入并返回 shell；独立读盘核对全部 1,048,576 字节 |
| `gui_shape` | QEMU 真实 scanout 中显示五组蓝圆、红框、绿三角；尺寸、代表像素、空心区域及颜色数量检查通过 |
| 镜像构建 | 主机端制作与独立读取器均支持双重间接块，1 MiB 文件回读一致 |

图形检查验证形状、位置和颜色，不要求不同语言绘图库的边界像素逐点一致。不设吞吐量或时延评分阈值。

## 动态跟踪

按照 `ucore-ch9-analyze.md` 的三个场景执行 GDB 跟踪：

- UART：观察到 `RUNNING → SLEEPING → RUNNABLE`，等待队列登记后，真实接收中断令缓冲从空变为非空。
- 块设备：提交 token 与等待条件变量对应；完成中断获得成功响应，处理 used ring，并把等待线程设为就绪。
- GPU：查询尺寸 1280×800、长度 4,096,000 字节；初始化、包装层及应用映射访问同一 DMA 帧缓冲，并命中显示刷新路径。

动态示例使用独立 QEMU 会话和磁盘副本，未通过 GDB 调用具有副作用的设备方法。

## 提供代码的集成检查

这些检查用于维护参考实现，不增加学生的任务或评分项：

- 主线程退出时取消等待串口的兄弟线程，随后重新运行文件验收成功。
- 主线程退出时保留已提交设备请求使用的内存，完成后再回收；随后文件验收成功。
- 一个兄弟线程持有文件系统操作、另一个等待文件系统锁时，进程退出能完成清理；随后文件验收成功。
- 八处考核函数与 `lab.json` 一致；学生版只将三份文件中对应区域替换为未实现标记。基础设施、用户程序与参考实现相同。
- 学生骨架已通过交叉编译；在独立工作树中仅补回八处函数体后，重新通过全部功能验收、显示检查与独立磁盘回读。
